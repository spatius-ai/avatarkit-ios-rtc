## 2026-08-26T16:46:37+08:00 — Fill `architecture/` against code at v1.0.0

**Scope:** Last of the seven SDK repos in the docs alignment pass. All four
architecture files were empty skeletons; each is now written against the code at
v1.0.0. Three parallel audits, each finding cited to `file:line` and
spot-checked before applying.

### What changed

All four written from scratch: `overview.md`, `telemetry-fields.md`,
`test-cases.md`, `release-process.md`, plus a regenerated `docs-map.md`.

### The finding that matters most

🔴 **`TelemetryIdentity.sdkVersion` has drifted, and this is the second time.**

`Sources/AvatarKitRTC/Utils/TelemetryIdentity.swift:25` still reads
`"1.0.0-beta.9"` while both podspecs say `1.0.0`. The
`52f258d release: v1.0.0` commit updated the podspecs and missed this file, so
**every telemetry record from v1.0.0 is stamped `1.0.0-beta.9`**.

It is a hand-written constant — a Swift package cannot read its own podspec — and
**nothing in the build catches it**. Its own comment (`:19-24`) records the same
thing happening before: stuck at beta.6 through the entire beta.7 release, fixed
only afterwards by `dc3aee9`.

Web injects this from package.json via vite's `define`; Android takes it from
`BuildConfig`. **iOS is the only one where it is typed by hand.** Recorded as the
first item of the version checklist in `release-process.md` §2, with the failure
mode spelled out.

### Problems hit

- **Rejected one audit finding after checking it.** The report claimed the
  simulator-architecture fix (`4e6c188`) landed *after* the `v1.0.0` tag, and
  therefore that the pod on trunk still had the bug and needed a patch release.
  `git rev-list -n1 v1.0.0` returns `4e6c188` — **the tag points at the fix
  itself**. Nothing to patch; not written into the docs.
- **Two of the three iOS-only test cases do not test what their names say.**
  `rtc.ios.avatar-id-mismatch` cannot build a payload with an arbitrary avatar id
  from outside the SDK, so it feeds empty `Data()` down the happy path, and its
  `catch` only logs — **it passes whether or not anything throws**.
  `rtc.ios.transition-end-smooth` asserts that an empty payload is rejected and
  never looks at whether the transition jumps. Documented by what they actually
  assert, not by their titles.
- **"Mock (no network)" is only true of the RTC link.** The credential check runs
  before the mode switch, and the runner still calls `AvatarSDK.initialize` and
  `AvatarManager.load` for real — mock needs a valid appID/avatarID and network,
  it just never talks to Agora. Android's phrasing would have been misleading if
  copied over.

Nine of the eleven defects catalogued for Android also hold on iOS; iOS avoids
two of them (log fields keep their native types, and `telemetry_kind` is a real
field rather than a comment's promise) and adds two of its own (the version drift
above, and `emitPlaybackTrace` having no try/catch where Android wraps it).

**The missing bucket registration is not an Android quirk** — the iOS main SDK's
`bucketProfiles` also lists only the 12 `rtc_playback_*` metrics, with
`rtc_transport` matching nothing. Web's main SDK registers all 20. Both mobile
platforms send four transport metrics into OTel's default buckets
(0/5/10/25/…/10000), which have no resolution for an RTT in milliseconds or a
percentage. Fixing it requires a main-SDK release on each platform.
