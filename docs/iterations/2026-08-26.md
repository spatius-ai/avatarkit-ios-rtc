### The finding that matters most

🔴 **`TelemetryIdentity.sdkVersion` has drifted, and this is the second time.**

`Sources/AvatarKitRTC/Utils/TelemetryIdentity.swift:25` still reads
`"1.0.0-beta.9"` while both podspecs say `1.0.0`. The
`52f258d release: v1.0.0` commit updated the podspecs and missed this file, so
**every telemetry record from v1.0.0 is stamped `1.0.0-beta.9`**.

It is a hand-written constant — a Swift package cannot read its own podspec — and
**nothing in the build catches it**. Its own comment (`:19-24`) records the same
thing happening before: stuck at beta.6 through the entire beta.7 release, fixed
only afterwards by `dc3aee9`.

Web injects this from package.json via vite's `define`; Android takes it from
`BuildConfig`. **iOS is the only one where it is typed by hand.** Recorded as the
first item of the version checklist in `release-process.md` §2, with the failure
mode spelled out.

## 15:40 — `TelemetryIdentity.sdkVersion` corrected, and made checkable

`TelemetryIdentity.swift` was left at `"1.0.0-beta.9"` when `52f258d release:
v1.0.0` bumped both podspecs. Set to `1.0.0`.

**Build-time injection was investigated and is not available.** Swift Package
Manager has no equivalent of Vite's `define` or Gradle's `buildConfigField`: a
package cannot read its own podspec, its git tag, or generate a constant at
build time. The main SDK has the same constraint and solves it the same way
(`AvatarSDK.swift:489`, `nonisolated public static var version: String
{ "1.3.3" }`). So the earlier open item — "should be injected at build time" —
has no implementation on this platform, and the constant stays hand-written.

What was wrong was not the hand-writing but that **nothing checked it**. Added
`scripts/check_version_consistency.sh`, which compares the constant against both
podspecs and exits 1 on any disagreement. Verified in both directions: it passes
on HEAD, and it fails with exit 1 when a podspec is perturbed. Wired into
`release-process.md` §3 (pre-release checklist) and §6 (release steps, before
`git tag`).

The script covers three of the five version sites. The podspec-internal cross
reference (`AvatarKitRTC.podspec:44`) and the git tag stay manual, and the docs
now say so rather than implying full coverage.

### Not fixed

**The shipped v1.0.0 artifacts cannot be corrected.** Every telemetry record
from that release carries `sdk_version = 1.0.0-beta.9`. Anyone reading v1.0.0
data needs to know this; it is recorded in `telemetry-fields.md` §0 and
`overview.md` rather than only in this log.
